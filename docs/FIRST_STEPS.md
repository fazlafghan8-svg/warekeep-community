# First steps with WareKeep Community

WareKeep Community is the public offline edition. Separate commercial services may be offered alongside it. Online accounts, subscription activation, payments, and cloud services are excluded from the Community source; shared code required for offline operation remains public. You do not need to be a programmer to understand the steps below.

## 1. Try the exact version you plan to use

Use a fresh test workspace with made-up information. Add a product with a quantity of 10 and sell 2. The remaining quantity should be 8. Close and reopen the application, then check the quantity and invoice. Export a backup, restore it into an empty test workspace, and reopen the application again.

A successful test of an older executable does not establish that a new version works. Test before relying on the application for real business records. Instructions for running the source and building the Windows application are in the [README](../README.md).

English is the default interface language for a fresh workspace. The initial calendar is Gregorian, and the time zone follows the device's local setting. You can select Persian/Dari in **Settings → General**. Changing the interface language does not convert existing currencies or amounts; review your business settings before entering real records.

## 2. Use the official Community repository

The official repository is [fazlafghan8-svg/warekeep-community](https://github.com/fazlafghan8-svg/warekeep-community). It contains the offline Community source and is separate from the owner's private development workspace.

If you help prepare a publication, upload only a reviewed Community source export. Do not upload the original mixed development folder, its private Git history, business records, backups, or deployment configuration. Read the [source scope](OPEN_SOURCE_SCOPE.md).

## 3. Understand the license

Apache-2.0 permits commercial use by the owner and other recipients. The owner may sell the application, separate commercial features, installation, training, and support. Rights to code already published under that license cannot simply be withdrawn from its recipients. Read the [plain-language explanation](COMMUNITY_LICENSE.md).

## 4. Report problems through the appropriate channel

For an ordinary bug, describe the application version, operating system, reproduction steps, and expected and actual behavior in the repository's [Issues](https://github.com/fazlafghan8-svg/warekeep-community/issues). Use made-up data in examples and screenshots.

Private vulnerability reporting is enabled. Use the repository's [Security advisories](https://github.com/fazlafghan8-svg/warekeep-community/security/advisories) and follow [SECURITY.md](../SECURITY.md). Do not post vulnerability details or private data in a public issue.

## 5. Build a record of real use

Share suitable test versions with interested users, fix reported problems, and publish feedback only with their permission. Record actual usage, downloads, and contributions; do not invent or estimate them as established facts. This helps explain the project's value to its users.

## 6. Consider an OpenAI support application

If you decide to apply, read the current [Codex for Open Source](https://developers.openai.com/community/codex-for-oss) page and follow its application link. Provide the real repository URL, your maintainer role, and verifiable evidence of use. Publishing open source does not by itself guarantee acceptance or six months of ChatGPT Pro. No OpenAI support application has been submitted for this project.

Check [GitHub Actions](https://github.com/fazlafghan8-svg/warekeep-community/actions) for workflow results associated with the version you plan to use. A successful result for another source version does not establish that your version passed.
